# Практическое занятие №18 — деплой HeartLink

## 1. Назначение работы

Выполняется локальная репетиция production-деплоя учебного веб-приложения HeartLink. Проект запускается на компьютере студента в Docker Compose. Публикация в открытом Интернете не выполняется.

## 2. Архитектура

```text
Браузер
  |
  | https://heartlink.localhost (443) / http://heartlink.localhost (80 → 301)
  v
nginx — единая точка входа, HTTPS, обратный прокси
  |
  | HTTP внутри сети Docker Compose
  v
app — Node.js 22 (production), API + HTML/CSS/JavaScript
  |
  +-- временное хранилище в памяти процесса
```

В проекте нет отдельной базы данных: текущая учебная версия хранит пользователей, сессии, лайки и пары в памяти Node.js. После перезапуска контейнера эти данные сбрасываются. Для реальной эксплуатации потребуется подключить постоянную базу данных и спроектировать резервное копирование.

## 3. Состав сервисов

| Сервис | Технология | Внутренний порт | Production-запуск |
|---|---|---:|---|
| `app` | Node.js 22, встроенный `node:http` | 3000 | `node server.js` |
| `nginx` | Nginx 1.30 Alpine | 80, 443 | Обратный прокси и HTTPS |
| База данных | Не используется | — | — |

Снаружи доступны только порты nginx, привязанные к `127.0.0.1`. Сервис `app` доступен только внутри сети Docker Compose.

## 4. Переменные окружения

| Имя | Назначение | Где используется |
|---|---|---|
| `NODE_ENV` | Режим production | Контейнер `app` |
| `PORT` | Порт Node.js-сервера | Контейнер `app` |
| `SITE_URL` | Канонический адрес сайта для SEO | Контейнер `app` |
| `SEED_DEMO` | Включение демонстрационных анкет (`true`/`false`) | Контейнер `app` |

Секреты для текущей версии не требуются: внешние сервисы и база данных не подключены. Закрытый ключ TLS создаётся локально и не коммитится в Git.

## 5. Подготовка HTTPS и домена

Требуются Docker Desktop с Docker Compose и утилита mkcert. В PowerShell от имени администратора выполните:

```powershell
winget install FiloSottile.mkcert
mkcert -install
```

Перейдите в папку `deploy` проекта и выпустите сертификат:

```powershell
mkcert -cert-file certs/heartlink.localhost.pem -key-file certs/heartlink.localhost-key.pem heartlink.localhost
```

Домен `.localhost` предназначен для локального компьютера, регистрировать его не нужно. Сертификат должен быть доверенным в операционной системе. Файлы `.pem` и закрытый ключ не отправляются в репозиторий.

## 6. Запуск и остановка

Все команды выполняются из папки `deploy`. При первом запуске создайте локальный файл настроек из примера (он не отправляется в Git):

```powershell
Copy-Item .env.example .env
```

Все команды запуска:

```powershell
# Сборка образа и запуск контейнеров

docker compose up --build -d

# Состояние контейнеров
docker compose ps

# Журналы приложения и nginx
docker compose logs app
docker compose logs nginx

# Проверка конфигурации nginx
docker compose exec nginx nginx -t

# Остановка контейнеров (данные приложения хранятся в памяти)
docker compose down
```

Откройте `https://heartlink.localhost`. При обращении к `http://heartlink.localhost` nginx должен перенаправить браузер на HTTPS. Для проверки API зарегистрируйте пользователя и откройте DevTools → Network.

Для демонстрационных анкет измените `SEED_DEMO=false` на `SEED_DEMO=true` в локальном файле `deploy/.env`, затем выполните `docker compose up --build -d`. Для обычного запуска оставьте `false`.

## 7. Проверки после запуска

- `docker compose ps`: сервисы `app` и `nginx` находятся в состоянии `Up`; у `app` проходит healthcheck.
- Страница открывается по `https://heartlink.localhost` без предупреждения о сертификате.
- HTTP перенаправляется на HTTPS.
- API доступен через тот же домен, например `/api/profiles` после авторизации.
- В ответах API присутствует `X-Robots-Tag: noindex, nofollow`.
- В Docker Desktop опубликованные порты `80` и `443` присутствуют только у nginx; у `app` опубликованных портов нет.

## 8. CI/CD

Workflow расположен в `../.github/workflows/build.yml`. При push, pull request и ручном запуске выполняются тесты и сборка Docker-образа. При push в ветку `main` после успешных тестов образ дополнительно публикуется в GitHub Container Registry (GHCR) с тегами `latest` и SHA коммита.

В текущем проекте один собственный контейнер приложения (`app`); nginx берётся из официального образа. Поэтому workflow собирает один пользовательский образ приложения. Публикация и автоматическое обновление локального компьютера не выполняются.

## 9. Ошибки и способы устранения

| Возможная ошибка | Что проверить |
|---|---|
| nginx не запускается, сертификат не найден | Выполнить mkcert из папки `deploy`, проверить имена файлов в `deploy/certs` |
| Браузер предупреждает о сертификате | Выполнить `mkcert -install`, перезапустить браузер |
| Порт 80 или 443 занят | Освободить порт или остановить программу, которая его использует |
| `app` unhealthy | Выполнить `docker compose logs app`, проверить запуск Node.js и `/health` |
| Изменения не появились | Выполнить `docker compose up --build -d` |
| GitHub Actions не публикует образ | Проверить права `packages: write` и настройки Workflow permissions |

Фактические ошибки, возникшие при выполнении на компьютере, следует вписать после запуска; таблица выше содержит типовые диагностические случаи.

## 10. Что потребуется для публикации на реальном сервере

Потребуется арендовать сервер или облачный хостинг, зарегистрировать домен и направить DNS-запись на сервер, получить публичный TLS-сертификат, настроить firewall, хранение секретов, постоянную базу данных и резервное копирование. Также потребуется обеспечить требования законодательства о персональных данных, включая применимые требования 152-ФЗ. Учебная версия HeartLink не предназначена для обработки реальных пользовательских данных.
